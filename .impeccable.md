## Design Context

### Users
Developers and evaluators testing the Capacitor-Lynx integration. They need to quickly see which plugins work, understand the support status, and interactively test plugin functionality in the iOS Simulator. The job to be done is demonstrate complete coverage of all official Capacitor plugins with the Lynx NativeModule bridge.

### Brand Personality
- **Professional** — clean, trustworthy technical demonstration
- **Clear** — unambiguous support status at a glance
- **Hybrid** — blends Capacitor's established brand with Lynx's modern identity

### Aesthetic Direction
- Base the design on Capacitorjs.com's clean, professional aesthetic with bright blue primary branding
- Incorporate subtle Lynx elements: the hexagonal gradient logo influence and brand energy
- Light mode primary (matching Capacitor site) with enough contrast for readability on mobile
- Clear visual hierarchy that groups plugins by category and uses color/badges to indicate support status
- Avoid dark AI aesthetics; go for crisp, open, modern like the official Capacitor site

### Design Principles
1. **Clarity first** — support status (full/interactive/partial/unsupported) must be immediately visible
2. **Brand harmony** — respect Capacitor's clean blue identity with subtle Lynx accents
3. **Modern spacing** — generous whitespace, clear visual rhythm that breathes on mobile
4. **Subtle refinement** — no excessive decoration; every visual element serves a purpose
5. **Interactive confidence** — buttons and tappable areas feel intentional and responsive

### Support Status Legend
- ✅ **Full Support** — automatic smoke test passes, no user interaction required
- 🖱 **Interactive** — works fully but requires user tap (modals, UI presentations, hardware sensors)
- 🔑 **Partial** — works but requires external configuration (API keys, credentials)
- ❌ **Unsupported** — cannot work in current demo environment (missing capabilities)
